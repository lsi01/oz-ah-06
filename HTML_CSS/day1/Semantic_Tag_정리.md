# Semantic Tag(시맨틱 태그) 정리

## 시맨틱 태그란

시맨틱(semantic, 의미론적) 태그는 화면에 어떻게 보이는지가 아니라, 그 영역이 문서에서 어떤 역할을 하는지를 태그 이름 자체로 드러내는 태그다. `<div>`로도 같은 화면을 만들 수 있지만, `<div>`는 이름만 봐서는 그 영역이 헤더인지 본문인지 알 수 없다. 시맨틱 태그를 쓰면 코드를 처음 보는 사람도, 그리고 스크린 리더 같은 보조 기술도 문서 구조를 곧바로 파악할 수 있다.

## 주요 시맨틱 태그

| 태그 | 역할 |
|---|---|
| `<header>` | 페이지 또는 특정 영역의 상단부. 로고, 제목, 소개 문구 등 |
| `<nav>` | 다른 페이지나 섹션으로 이동하는 내비게이션(메뉴) 링크 모음 |
| `<main>` | 문서의 핵심 콘텐츠. 페이지당 하나만 사용하는 것이 원칙 |
| `<article>` | 그 자체로 독립적으로 의미가 완결되는 콘텐츠(블로그 글, 뉴스 기사 등) |
| `<section>` | 문서 안에서 주제로 묶이는 하나의 구획(예: "소개", "가격 안내") |
| `<footer>` | 페이지 또는 특정 영역의 하단부. 저작권 정보, 연락처 등 |

## article과 section의 차이

가장 헷갈리기 쉬운 두 태그다. `<article>`은 그 부분만 떼어내 다른 곳에 옮겨놓아도 독립적으로 말이 되는 콘텐츠(블로그 포스트 한 편, 댓글 하나)에 쓰고, `<section>`은 한 문서 안에서 주제 단위로 묶이는 구획(랜딩 페이지의 "기능 소개" 구획, "고객 후기" 구획)에 쓴다. 실무 기준으로는, 제목(`<h1>`~`<h6>`)을 붙일 수 있는 독립된 콘텐츠 덩어리인지를 기준으로 판단하면 구분이 쉽다.

## 예시 구조

```html
<body>
  <header>
    <h1>블로그 이름</h1>
    <nav>
      <a href="/">홈</a>
      <a href="/about">소개</a>
    </nav>
  </header>

  <main>
    <article>
      <h2>글 제목</h2>
      <section>
        <h3>도입부</h3>
        <p>...</p>
      </section>
      <section>
        <h3>본문</h3>
        <p>...</p>
      </section>
    </article>
  </main>

  <footer>
    <p>&copy; 2026 blog</p>
  </footer>
</body>
```

## div와의 관계

시맨틱 태그를 쓴다고 `<div>`를 아예 쓰지 않는 것은 아니다. 여러 요소를 하나로 묶어 CSS 스타일(정렬, 레이아웃)을 일괄 적용하기 위한 용도로는 `<div>`가 여전히 자연스럽게 쓰인다. 즉 "그 영역이 문서 구조상 의미를 갖는가"라면 시맨틱 태그를, "스타일링을 위해 그냥 묶어야 하는가"라면 `<div>`를 선택하는 것이 기준이 된다. (자세한 내용은 [div_태그_정리.md](./div_태그_정리.md) 참고)
