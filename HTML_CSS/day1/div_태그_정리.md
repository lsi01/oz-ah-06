# &lt;div&gt; 태그 정리

## div란

`<div>`(division)는 특별한 의미나 기본 스타일 없이, 단순히 화면의 한 영역을 구획으로 나누는 태그다. `<h1>`이나 `<table>`처럼 태그 자체에 정해진 역할이 없기 때문에, 사실상 어떤 레이아웃이든 div만으로 만들어낼 수 있는 만능 태그에 가깝다.

```html
<div>
  <div>제목 영역</div>
  <div>본문 영역</div>
</div>
```

## div만으로 화면을 만들면 생기는 문제

화면 전체를 div로만 채우면 각 태그가 어떤 역할을 하는지 태그 이름만으로는 전혀 알 수 없다. 다른 사람이 작성한 코드를 넘겨받았을 때 전부 `<div>`로만 되어 있다면 어디서부터 봐야 할지 파악하기 어렵고, 스크린 리더 같은 보조 기술도 "이 영역이 내비게이션인지 본문인지" 구분할 근거가 없다. 이 문제를 줄이기 위해 `<header>`, `<main>`, `<footer>` 같은 시맨틱 태그가 쓰인다.

## 그럼에도 div가 필요한 경우

div가 시맨틱하지 않다고 해서 쓰면 안 되는 태그는 아니다. 다음과 같은 경우에는 여전히 div가 자연스러운 선택이다.

- **여러 요소를 하나로 묶어 스타일을 일괄 적용할 때**: 예를 들어 세 개의 텍스트를 하나의 `<div>`로 감싸고, 그 부모 div 하나에만 `text-align: center;`를 지정하면 Cascading 성질에 따라 자식 전체가 한 번에 가운데 정렬된다.
- **레이아웃을 위한 컨테이너가 필요할 때**: Flexbox나 Grid로 배치를 잡을 때, 그 배치 기준이 되는 감싸는 요소로 흔히 div를 쓴다.
- **의미상 시맨틱 태그 어디에도 맞지 않는 순수 스타일용 구획일 때**: 예를 들어 배경색만 다르게 주기 위한 래퍼(wrapper) 같은 경우.

## 판단 기준 정리

| 상황 | 선택 |
|---|---|
| 이 영역이 문서에서 특정 역할(헤더, 내비게이션, 본문 등)을 한다 | 시맨틱 태그(`header`, `nav`, `main` 등) |
| 여러 요소를 묶어 스타일만 일괄 적용하면 된다 | `<div>` |
| 시맨틱 태그로 표현하기 애매한 순수 레이아웃용 래퍼다 | `<div>` |

정리하면, div는 "의미 없는 태그"라기보다 "의미를 강제하지 않는 태그"에 가깝다. 문서 구조상 의미가 분명한 부분은 시맨틱 태그로 표현하고, 순수하게 스타일링·레이아웃을 위해 묶어야 하는 부분에는 div를 쓰는 것이 시맨틱 HTML과 div를 함께 쓰는 실무 기준이다.
